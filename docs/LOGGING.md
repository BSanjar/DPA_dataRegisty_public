# Логирование

Serilog, схема как в Abilling: читаемый текст, асинхронная запись (логирование не тормозит и не роняет запросы),
папка на категорию, файл на день, все ошибки дополнительно собираются в `errors`.

```
/logs/registry_public/
  auth/auth_20261020.log                 вход через ЕСИ, регистрация пользователей, привязка организации, выход;
                                         действия пользователей: регистрация инцидентов
  integration/integration_20261020.log   запросы и ответы Минюста (ИНН → реквизиты, время ответа), ЕСИ (токен, userinfo — только статус)
  system/system_20261020.log             старт/остановка, миграции при запуске, проблемные HTTP-запросы (5xx, дольше 5 с), прочее
  errors/errors_20261020.log             копия ЛЮБОЙ записи Error/Fatal из всех категорий
/logs/registry_local/                    то же для локальной части (админки)
```

Формат строки:

```
[2026-10-20 16:43:19.710] [INF] [9eef5ff2-6718-43eb-ac75-819b79290e8b 10.0.0.15] [0HNPEIROK9F41:00000005] data_registry_public.Integrations.MinJustService: Минюст ← HTTP 200 за 312 мс: {...}
 время (Бишкек)            уровень  пользователь, IP   id запроса (общий для всех строк запроса)   источник: сообщение
```

По id запроса строку из `errors` можно связать с записями в других файлах.

## Что не пишется

* Пароли, токены, ответы ЕСИ: в них секреты и персональные данные, поэтому пишется только статус. Ответ Минюста пишется, обрезанный до 4000 символов.
* Query string запросов.
* Обычные HTTP-запросы. В `system` попадают только ошибки 5xx и запросы дольше 5 с.
  Полный журнал запросов включается через `Logging:MinimumLevel=Debug`.
* Запросы `HEAD` (проверки доступности) и статика.
* ФИО и ПИН в поле пользователя: там внутренний id (`public_users.id`). ПИН в тексте сообщений маскируется (`***0123`).

## Настройки (`appsettings.json` → `Logging`)

| Ключ | По умолчанию | |
|---|---|---|
| `Directory` | локально `{ContentRoot}/logs/registry_public`, в контейнере `/logs/registry_public` | папка логов |
| `RetainedFileCountLimit` | `90` | сколько файлов (дней) хранить на категорию |
| `MinimumLevel` | `Information` | `Debug` включает подробные логи и полный журнал запросов |
| `Console` | `true` | дублировать в stdout (`docker logs`) |

Если за день файл вырастает больше 50 МБ, запись продолжается в `_001`, `_002`. Для Microsoft и EF Core пишутся
только Warning и выше, так что ошибки SQL попадают в `errors`.
Если папка недоступна на запись, приложение всё равно стартует: логи пишутся во временную папку,
а в `system` и `errors` появляется ошибка с причиной.

## Публикация

Образ создаёт `/logs/registry_public` с правами пользователя приложения, выставляет `TZ=Asia/Bishkek`
и объявляет том `/logs`. На сервере монтируется один общий каталог `/logs` для обеих частей.

Команды `docker run` с томами и режимом — в `docs/RUN.md`.

* `--log-opt max-size/max-file` ограничивает stdout-лог Docker (по умолчанию он растёт без предела).
  Консоль можно отключить совсем: `-e Logging__Console=false`.
* Время в логах и в приложении бишкекское. Без `TZ` контейнер работал бы в UTC.

## Поиск

```bash
grep -h "Минюст" /logs/registry_public/integration/*.log | tail
grep -h "0HNPEIROK9F41:00000005" /logs/registry_public/*/*.log      # всё по одному запросу
tail -f /logs/registry_public/errors/errors_$(date +%Y%m%d).log
```

## В коде

`ILogger<T>` как обычно. Категория определяется по классу (карта в `Program.cs`), всё остальное попадает в `system`.
Явно задать категорию для блока кода:

```csharp
using (LogCategories.Push(LogCategories.Integration)) { _logger.LogWarning("..."); }
```

Параметры сообщений называйте по смыслу (`{Tin}`, `{UserId}`). ПИН пишите только через `AppLogging.Mask(...)`. Служебные поля строки называются
`LogUser`, `LogIp` и `LogCategory`, поэтому `{User}` или `{Category}` в тексте сообщения их не перебьют.
